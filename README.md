# Retail Analytics: Complete Journey 2017

End-to-end analytics on **1.46 million real grocery transactions** from 2,469
households (84.51° / dunnhumby "The Complete Journey"). The project covers
ingestion with checksums, a DuckDB star schema with a blocking data-quality gate,
a governed metric layer, a 13-query SQL analysis library, statistical tests of
campaign, coupon and promotion impact, a Streamlit app with an ask-the-data
copilot, and a Power BI report whose DAX is verified against the SQL.

## Key findings

Every number is generated by `python -m retail.analytics`; full tables are in
[`reports/insights.md`](reports/insights.md) and the test outputs are in
[`reports/stats_results.json`](reports/stats_results.json).

| # | Finding | So what |
|---|---|---|
| 1 | **About half of coupon redemptions subsidise purchases that were already happening.** 50.6% (95% CI 48.5–52.8%) came from households that bought the same product in the previous 56 days; 54.5% for Type A campaigns. | Stop sending a product's coupon to its recent buyers. |
| 2 | **Campaign ROI cannot be measured with the current design.** A difference-in-differences test against never-targeted households **fails its placebo check for all 3 campaign types**: targeted households were already spending less than controls (by up to $5.26/week) before launch. | Targeting picks declining shoppers. Hold out a random 10% of every list. |
| 3 | **In-store support compounds.** Against the same product in the same store, a mailer alone lifts sales +131%, a display alone +129%, and both together **+225%** (CI 220–231%). | Pair mailer features with displays. |
| 4 | **Q4 growth came from bigger baskets, not more trips.** Sales were +6.2% vs Q3, basket value +7.4%, trips −1.1%. | Growth is spend-per-visit led. |
| 5 | **Own-brand gap in soft drinks.** $182K of sales, only 11.4% private label, although own brand is priced 46% below national brands. Frozen pizza shows the same pattern. | Largest private-label opportunity. |
| 6 | **Sales are concentrated.** The top 10% of households drive 34.2% of sales; the top 20% drive 53.5%. 314 at-risk frequent shoppers hold 13.5%. | Prioritise retention and win-back. |
| 7 | **The business runs on deals.** 73% of households buy 40% or more of their spend on loyalty discount. | Price-investment decisions dominate margin. |
| 8 | **Weekend afternoons have the biggest baskets** ($36 vs about $28 on weekdays). Onions and potatoes are bought together 4.6x more often than chance. | Staffing, promotion timing and cross-merchandising. |

## The real-world data problems this project solved

These are the decisions an analyst has to make with real data, and the quality
gate enforces each one on every build.

- **Timestamps are UTC, the stores are not.** Hourly baskets peaked at "17:00 UTC"
  and the retailer's week boundaries sat at 05:00 / 04:00 UTC. That is local
  midnight in US Eastern time, with the switch at daylight saving. Business dates
  now use Eastern time and reproduce the retailer's week number on **all 1.46M
  rows**. An earlier fixed 05:00 cut-off was caught by the gate: 785 rows fell in
  the wrong week during DST.
- **Fuel quantities are not units.** Gasoline lines carry quantities up to
  89,638, so `units` is NULL for fuel.
- **Gift cards are not revenue.** Gift card activations are liabilities, so they
  are excluded from merchandise sales.
- **Orphan lines:** 4,836 transaction lines reference unknown products. They are
  quarantined, not deleted, and landing = fact + quarantine reconciles to the cent.
- **The promotions feed lists only promoted weeks** (no "not promoted" rows), and
  12,785 keys are duplicated. The baseline is built from the weeks a product is
  absent from the feed.
- **The coupon master has 1,623 duplicate rows.** Demographics cover only 32% of
  households, so demographic findings say so.

[`docs/methodology.md`](docs/methodology.md) documents every decision.

## Architecture

```text
 completejourney (CC0)      ingest.py            transform.py (sql/models)        quality.py
 8 R files, SHA-256  ──►  Parquet landing  ──►  staging ─► marts (star schema) ──► 23 checks
                                                     │                              (errors block)
                       metrics.py (semantic layer)   ▼
                       sql/analysis/*.sql  ──►  DuckDB warehouse  ──►  stats.py (DiD, Wilson, bootstrap)
                                                     │
               ┌─────────────────────┬───────────────┼────────────────────┬─────────────────────┐
         Streamlit app        copilot.py         analytics.py       export_powerbi.py      evaluate.py
         8 tabs               governed SQL +     insights.md        Parquet ─► Power BI    16 golden Qs
                              cited docs, audit                     (TMDL + PBIR)          CI gate
```

| Layer | Tables |
|---|---|
| Facts | `fct_sales` (line), `fct_baskets` (trip), `fct_campaign_targets`, `fct_coupon_redemptions`, `fct_promotions` (product × store × week) |
| Dimensions | `dim_product`, `dim_household`, `dim_date` (trading calendar, holidays), `dim_campaign`, `dim_coupon` |

## What's inside

| Component | Where | Notes |
|---|---|---|
| Ingestion | `src/retail/ingest.py` | Downloads the source, records SHA-256 checksums, lands Parquet |
| SQL models | `sql/models/` | Staging → marts, dbt-style layering; every exclusion is a flag |
| Data quality gate | `src/retail/quality.py` | 23 declarative checks (reconciliation, keys, referential integrity, validity); errors block the pipeline, warnings are documented |
| Metric layer | `src/retail/metrics.py` | One definition per KPI; a test asserts that the SQL library and Power BI agree |
| SQL library | `sql/analysis/` | 13 analyses: KPIs, trends, departments, private label, deal dependence, RFM, deciles, demographics, campaigns, coupon incrementality, promotion lift, market basket, shopping times |
| Statistics | `src/retail/stats.py` | Difference-in-differences with clustered SEs and a placebo test, Wilson intervals, bootstrap CIs |
| App | `app.py` | Overview, Customers, Campaigns & coupons, Promotions & pricing, Ask the data, SQL runner, Data quality, Audit log |
| Copilot | `src/retail/copilot.py` | Routes to the SQL library, metric-layer templates or BM25 doc retrieval; cites sources; audit log; optional LLM-written SQL through the guard |
| SQL guard | `src/retail/sql_guard.py` | One SELECT only, keyword blocking, read-only connection with **external file access disabled**, row cap |
| Power BI | `powerbi/` | Star schema, 25 DAX measures, 5 pages; report-as-code generator |
| Evals | `evals/`, `src/retail/evaluate.py` | 16 golden questions, 100% pass, CI fails below 90% |
| CI / Docker | `.github/workflows/ci.yml`, `Dockerfile` | Unit job on SQL fixtures, plus a data job that runs the real pipeline and the eval gate |

## Power BI report

[`powerbi/Retail_Analytics.pbip`](powerbi/Retail_Analytics.pbip) has five
pages: Executive Overview (Q4 vs Q3), Trends, Customers, Campaigns & Coupons,
and Own Brand & Discounts.

**The DAX is verified against the SQL.** Each measure was run against the live
model and matches the SQL library: quarterly sales, baskets, basket value,
discount rate, own-brand share, QoQ deltas, weekly WoW growth, 4-week rolling
average, top-10% share (34.2%), department scorecard, and campaign redemption
rates (16.6% / 6.5% / 5.9%).

Verification caught two bugs:

- **Context transition.** `VALUES()` inside a `CALCULATE` filter argument ignores
  row context, which inflated the redemption rate from 6.5% to 83%. Fixed with a
  variable.
- **Off-by-one decile.** The top-10% household count was rounded up instead of
  down.

**To open it:** run the pipeline, open the `.pbip` in Power BI Desktop, set
`DataFolder` (Transform data → Manage parameters) to your `powerbi/data/`
folder, then Refresh.

## Quick start

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
set PYTHONPATH=src                   # macOS/Linux: export PYTHONPATH=src
python -m retail.pipeline            # about 1 minute: download, build, quality gate, stats, report, Power BI export
streamlit run app.py
```

```bash
pytest -q                            # 47 tests: SQL models on fixtures, guard, warehouse, metrics parity, copilot
python -m retail.evaluate --min 0.9  # copilot scorecard
```

On machines with less than about 8 GB of RAM, set `RETAIL_SKIP_TABLES=promotions`
to skip the 20.9M-row promotions file (CI does this). Stop the Streamlit app
before rebuilding: DuckDB locks the warehouse file while the app has it open.

## Limitations

- **Panel, not store totals.** Sales are the purchases of 2,469 loyalty
  households, not total store sales.
- **No cost data,** so the project reports sales, discount and mix, not margin.
- **Promotion lift is an upper bound,** because promotions are not randomly
  assigned. The campaign test shows observational targeting cannot identify ROI.
- **The coupon "habitual" share is a proxy for non-incrementality,** not a causal
  estimate.
