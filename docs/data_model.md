# Data model

_Generated by `python -m retail.docs_gen`. Row counts are from the current warehouse._

A star schema in DuckDB. SQL models build it in layers: `sql/models/01_staging.sql` (typed and flagged source data), `02_marts.sql` (facts and dimensions) and `03_segments.sql` (segments and derived facts).

## Tables and grain

| Table | Grain | Key | Joins to | Rows |
| --- | --- | --- | --- | ---: |
| `fct_sales` | One merchandise or non-merchandise transaction line with a known product | basket_id + product_id + line | dim_product, dim_household, dim_date | 1,464,471 |
| `fct_baskets` | One shopping trip (merchandise lines only) | basket_id | dim_household, dim_date | 141,180 |
| `fct_campaign_targets` | One campaign x targeted household | campaign_id + household_id | dim_campaign, dim_household | 6,589 |
| `fct_coupon_redemptions` | One coupon redemption | household + coupon_upc + campaign + date | dim_household, dim_campaign, dim_coupon | 2,102 |
| `fct_promotions` | One promoted product x store x retail week | product_id + store_id + week | dim_product | 20,927,744 |
| `quarantine_transactions` | One rejected transaction line (unknown product) | - | - | 4,836 |
| `dim_product` | One product | product_id | - | 92,331 |
| `dim_household` | One shopping household | household_id | - | 2,469 |
| `dim_date` | One trading day in 2017 (US Eastern) | date_key | - | 365 |
| `dim_campaign` | One campaign | campaign_id | - | 27 |
| `dim_coupon` | One coupon x product x campaign | coupon_upc + product_id + campaign_id | - | 111,332 |
| `mart_household_segments` | One household with merchandise sales: RFM and deal segment | household_id | dim_household | 2,467 |
| `mart_coupon_redemptions` | One redemption with is_scored / is_habitual flags | redemption_id | dim_household | 2,102 |
| `mart_basket_affinity` | One category pair bought together | category_a + category_b | - | 780 |

## Relationships

| From | To | Cardinality |
| --- | --- | --- |
| `fct_sales.product_id` | `dim_product.product_id` | many-to-one |
| `fct_sales.household_id` | `dim_household.household_id` | many-to-one |
| `fct_sales.business_date` | `dim_date.date_key` | many-to-one |
| `fct_baskets.household_id` | `dim_household.household_id` | many-to-one |
| `fct_campaign_targets.campaign_id` | `dim_campaign.campaign_id` | many-to-one |
| `fct_campaign_targets.household_id` | `dim_household.household_id` | many-to-one |
| `fct_coupon_redemptions.(coupon_upc, campaign_id)` | `dim_coupon.(coupon_upc, campaign_id)` | many-to-many* |
| `fct_coupon_redemptions.household_id` | `dim_household.household_id` | many-to-one |
| `fct_promotions.product_id` | `dim_product.product_id` | many-to-one |

\* A coupon applies to many products, so a redemption maps to several `dim_coupon` rows. Queries join on product only when they need it (the habitual check), never to sum sales.

## Power BI model

The Power BI model (`powerbi/Retail_Analytics.SemanticModel`) imports the same tables from Parquet (`python -m retail.export_powerbi`): **Sales** (fact, merchandise lines only) with single-direction many-to-one relationships to **Product**, **Household** and **Date** (marked as the date table). **Coupon Redemptions** relates to Household and Date, and **Campaign Targets** relates to Household. The Basket Affinity, Promotion Lift and Campaign Tests tables are stand-alone results tables.
